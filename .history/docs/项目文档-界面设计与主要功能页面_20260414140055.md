# 1.1 界面与功能说明

## 1.1.1 界面设计风格

本项目主页面采用“叙事型信息架构 + 任务导向交互”的设计思路，整体视觉和布局均围绕病理分析场景展开，强调专业性、可信度与可解释性。为了便于报告展示，页面设计可以按具体视图来说明：各页面既保持统一风格，又在布局、图标与图像表达上体现各自功能定位。以下可在对应段落后插入页面截图，形成“图文对照”的报告结构。

首页视图承担系统入口与品牌展示功能，整体采用首屏聚焦式布局，顶部突出项目名称与核心定位，中部展示系统能力和场景说明，底部承接导航入口。页面图标与按钮以简洁、明确为主，主要用于跳转和场景引导，不做复杂装饰。图像风格上以深色科技感背景配合医学影像元素为主，形成稳定的视觉识别，突出“病理 + AI”这一核心主题。

工作流展示页视图主要用于呈现病理分析流程，页面结构通常为“阶段导航 + 主展示区”的组合。左侧或上方区域用于标明当前流程阶段，右侧或中部区域用于展示对应阶段的图像、卡片和过渡效果，帮助用户理解从输入切片到报告输出的完整路径。该页面的图标设计重点在于步骤徽章、阶段箭头和状态提示，功能上用于明确每个步骤的作用与先后关系；图像风格则偏向流程化、叙事化，强调连续性与可解释性。

切片处理页视图是系统的核心操作界面，采用工作台式布局，将文件上传、任务状态、进度日志、报告预览和中间结果分区呈现。图标与按钮设计主要服务于实际操作，例如上传、下载、刷新和取消等功能均采用明确的操作图标或按钮样式，便于用户快速识别。页面图像风格延续深色科技背景，同时搭配报告预览、patch 缩略图和结构化结果卡片，使“过程透明、结果可交付”的特点更加直观。

AI 架构图页视图主要面向技术说明与研发沟通，使用可交互流程图展示模型推理与报告生成链路。页面中的节点以模块卡片形式呈现，图标和连线用于说明输入、处理、评估和输出之间的关系，其中 Critic 评估节点是核心逻辑之一，负责判断是否需要回流 refine。为了避免页面过于拥挤，当前图示保持简化，但仍保留病理报告与诊断报告两个输出结果，从而在图像风格上兼顾简洁性与业务完整性。

综上，界面设计风格并不是单纯追求视觉装饰，而是通过统一的页面语言、清晰的布局结构、功能明确的图标和业务相关的图像风格，把系统的认知入口、流程展示、任务处理和技术说明组织成一个连贯整体。

## 1.1.2 主要功能页面

项目围绕“样本处理、流程演示、技术解释、入口导航”构建了四类主要功能页面，这些页面既可以分别独立使用，也可以串联成完整的演示与操作闭环。为了便于报告表达，下面按页面逐一说明其功能定位、设计特点和操作方式。

首页主要承担统一入口与产品概览的作用，用户首先通过首页了解系统定位，再进入具体功能页面。该页面通常保留较强的引导性，重点突出主标题、核心介绍和跳转入口，便于用户快速建立对整个系统的第一印象。

工作流展示页面主要用于流程演示，适合向用户说明病理分析是如何一步一步完成的。该页面突出“阶段切换”和“过程展示”，用户可通过滚轮、点击阶段按钮等方式查看不同步骤的内容，重点理解上传、分类、分块、相似检索以及报告生成之间的逻辑关系。

切片处理页面是系统的实际业务操作页面，用户在这里完成 WSI 文件上传、任务创建、进度查看和结果下载。任务执行过程中，页面会持续展示日志、进度和中间产物，处理完成后还可查看病理报告、诊断报告以及诊断 JSON 和 patch 结果。该页面更强调操作性和结果可追踪性，是系统最核心的功能入口之一。

AI 架构图页面主要面向研发说明和技术沟通，用于展示系统内部的推理流程与报告生成机制。页面采用流程图方式组织节点关系，保留从输入切片、特征提取、证据筛选到报告生成和 Critic 评估的逻辑闭环，并最终输出病理报告与诊断报告。该页面适合用于项目评审、方案汇报和技术解释。

总体来看，这四类页面分别对应系统的入口、演示、操作和技术说明四个层面，彼此之间既保持功能分工，又在视觉和交互上形成统一风格，从而保证文档叙述和实际页面体验的一致性。
